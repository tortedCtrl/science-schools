# План завершения разработки: 10 ноября — 25 декабря 2026 года

**Статус:** рабочий план команды на 45 дней. **Цель:** к 25 декабря получить воспроизводимый демонстрационный продукт, который сначала показывает сообщества выбранного человека, затем граф авторов и их соавторства по выбранной теме с выделенными сообществами и, наконец, список наиболее релевантных этой теме людей. Leiden и BigCLAM, фильтры, качество и производительность поддерживают эти три сценария.

## Рамки и исходное состояние

- В исходном снимке репозитория есть импорт OpenAlex, PostgreSQL, Leiden, API авторов и графа, React-интерфейс и CI сборки backend. UI сейчас загружает весь граф и фильтрует его в браузере. Автоматических тестов backend и frontend в репозитории пока нет.
- Код BigCLAM и тем находится в отдельных ветках `bigclam`, `theme`, `theme-computing`. Его интеграция, проверка и исправление входят в план; наличие веток не означает готовность функций.
- [PRD](PRD.md) шире этого плана и местами относит второй алгоритм за рамки пилота. На эти 45 дней приоритет имеет данный документ: BigCLAM, темы и фильтры включены по прямому решению команды. Остальные пункты PRD не становятся задачами автоматически.
- Новую работу добавляем только после замены задачи сопоставимой трудоёмкости и записи причины в этом документе. До 25 декабря выполняются только перечисленные ниже задачи и исправления, без которых их критерии приёмки не выполняются. Все задачи в плане обязательны.

## Какие сценарии должны работать в продукте к финалу

1. **Человек → его сообщества.** Найти автора по имени или ID, открыть его карточку и увидеть сообщества выбранного прогона, участников и совместные публикации. Для Leiden показывается одно сообщество, для BigCLAM — все принадлежности с коэффициентами; можно перейти к графу и подсветить выбранное сообщество. Это первый сценарий, который команда доводит до рабочего состояния.
2. **Тема → граф авторов с выделенными сообществами.** Выбрать тему и увидеть граф, где **узлы — авторы, а рёбра — их совместные публикации по выбранной теме**. Сообщества, рассчитанные заранее на общем графе соавторства, обозначены цветом или подсветкой; алгоритм не запускается заново для каждой темы. Можно выбрать Leiden или BigCLAM, период, организацию и минимальное число совместных работ, открыть автора, его сообщества и статьи, объясняющие ребро. Граф ограничен по объёму; видны число найденных авторов и причина скрытия остальных. Люди с редкой для своего сообщества темой не исключаются только потому, что тема не входит в топ тем сообщества.
3. **Тема → список авторов.** Из поиска темы или из узла графа получить постраничный список авторов, публиковавших работы по этой теме, независимо от того, попало ли их сообщество в граф. Порядок определяется документированной формулой тематической релевантности; рядом с каждым автором показаны число и примеры подходящих публикаций. Сортировка отражает только данные по выбранной теме.

Во всех трёх сценариях сообщества выводятся из структуры соавторства, а темы — из публикаций. «Сообщество» не равно «дисциплина» и не является подтверждённой научной школой.

**Порядок разработки и приёмки:** сначала сценарий 1 (T01–T03, T06–T08), затем сценарий 2 (T04–T08), затем сценарий 3 (T05–T07). Тестирование, сравнение алгоритмов, измерения и рефакторинг идут параллельно, но не меняют этого порядка продуктовой приёмки. Идентификаторы задач нужны для отслеживания, а не обозначают их важность.

Leiden и BigCLAM используют явно описанные правила; показывается покрытие темами и число статей. |

Использовать существующий агрегат для запроса по `topic_id` и добавить индекс под такой запрос; для списка людей создать `author_topic` или эквивалентный заранее посчитанный индекс. Зафиксировать формулу тематической релевантности автора (число отдельных работ и их OpenAlex `score`, с оговорённым периодом). Оба результата выдаются с сортировкой и пагинацией, без обхода всех авторов или статей на каждый запрос; переимпорт и новый запуск алгоритма обновляют данные. |
| T06 | P0 / backend + frontend | Зафиксировать и реализовать API трёх сценариев и фильтров | Есть поиск автора по имени/ID, получение **всех** его сообществ в выбранном прогоне, поиск темы с подсказками, граф авторов по `topic_id`, список авторов по `topic_id` и карточки публикаций. Для тематического графа сервер выбирает публикации по теме и периоду, включает их авторов как узлы **даже без тематических соавторских связей**, строит рёбра между соавторами подходящих статей и подгружает принадлежности авторов к заранее рассчитанным сообществам. Поддерживаются фильтры организации, алгоритма, сообщества и минимального числа подходящих совместных работ. Параметры, сортировка, ограничение размера ответа и ошибки описаны в контракте; фильтрация выполняется до передачи данных. |
| T07 | P0 / frontend | Сделать интерфейс в порядке трёх сценариев | Основной вход — поиск человека и его сообществ. Третий — вкладка/переход к списку людей по теме с объяснением порядка выдачи. ## Общие правила проверки и приёмки

- **Один набор данных для сравнения.** Фиксируются источник/дата снимка, правила построения графа (включая вес ребра и фильтры), версии кода, параметры и seed. Результаты разных прогонов хранятся раздельно. Для качества тем используют также вручную проверенные примеры: оценивать темы только теми же OpenAlex-метками, из которых они посчитаны, недостаточно.
- **Не смешивать коэффициенты.** BigCLAM выдаёт неотрицательные силы принадлежности (F), а не готовые вероятности. OpenAlex `score` относится к теме **конкретной публикации**. Порог принадлежности, нормировка и формула вклада статьи записываются в T03–T04 до реализации массовой агрегации. Статьи разных тем на одном ребре должны давать разные вклады.
- **Фильтр имеет одну семантику.** Тема/год применяются к публикациям, затем по оставшимся публикациям формируются связи и их веса; фильтр организации применяется к авторам по оговорённому правилу. Количество совместных работ считается после фильтра периода/темы. Интерфейс показывает активные фильтры и число найденных результатов.
- **Критерий финальной приёмки:** все T01–T16 имеют проверяемые результаты; сборка, clang-tidy, unit- и интеграционные тесты backend, сборка/lint, компонентные и сквозные тесты frontend проходят в CI; три сценария раздела «Какие сценарии должны работать в продукте к финалу» демонстрируются **в указанном порядке** на одном сохранённом снимке; отчёт T11 и измерения T12–T13 приложены; ограничение скорости/качества, если оно осталось, явно описано.

### Методические источники

- [Исходная статья BigCLAM](https://cs.stanford.edu/people/jure/pubs/bigclam-wsdm13.pdf): (F_{u,c} \ge 0) — сила связи автора с сообществом; вероятностная модель относится к возникновению **рёбер**.
- [Описание тем OpenAlex](https://help.openalex.org/data/topics/): `topics` и `score` принадлежат публикации; при импорте надо сохранить идентификатор темы, оценку и версию/дату источника.
